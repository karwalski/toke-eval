# Gate-1 60 — v0.4 solutions (133.4)

The 60 Gate-1 task ids KERN benchmarked (`task-a-0001`..`task-a-0060`, see
`toke/docs/about/reviews/kern-2026-08.md` §6), re-delivered as v0.4 programs that
compile with `tkc --check` and pass every hidden test case. Provenance:

- **originals** (April Gate-1 model output, v0.3 syntax): `git show 851f6d8b:benchmark/solutions/<id>.toke`;
- **pre-133.4 HEAD copies** (the 130.2 mechanical migration): `benchmark/solutions-pre133/` (57 files; the other 3 were byte-identical);
- **this set**: `benchmark/solutions/task-a-00{01..60}.toke`, each stored as its `tkc --min` canonical form (idempotent).

**Methodology.** Each solution is the `tkc --min` canonical form of the v0.4 program;
cl100k/o200k are `tiktoken` counts of that `--min` text (stripped), exactly the call
`kern-2026-08.repro.py` uses for the toke lanes (`encode(text, disallowed_special=())`);
tests are the hidden test cases (120 per task) executed through
`benchmark/run_benchmark.py`'s toke loader (`tkc --out bin src`, then `bin <json-input>`,
stdout parsed as JSON and deep-compared to `expected`).

**Harness command** (the hidden tests for 0001–0060 are not in this checkout's
`benchmark/hidden_tests/`, which holds 0501–1000; point `--tasks-dir` at a directory holding
the 60 YAMLs — the archived copy is byte-identical for the ids present in both):

```
TKC=~/tk/toke/tkc python3 benchmark/run_benchmark.py --language toke \
    --solutions-dir benchmark/solutions --tasks-dir <dir with task-a-0001..0060.yaml> \
    --output /tmp/gate1-60.json            # -> Pass@1: 60/60
TKC=~/tk/toke/tkc python3 scripts/gate1_60_v04.py --tests-dir <same dir> \
    --md docs/gate1-60-v04.md --json /tmp/gate1-60-v04.json   # regenerates the block below
```

The drop comes from writing the programs the v0.4 way (expression-`if`, `%`, `&&`,

frame (≈20 cl100k per program, ≈1,200 of the 4,787) plus `j.parse(s.argv(1))`.

- **27 ids are pure `tkc --migrate` output** (no hand edit): 0001, 0003, 0004, 0008, 0009,
  0018, 0020–0025, 0029, 0030, 0036–0041, 0044–0047, 0050, 0052, 0060.
- **Residue after migrate (2):** 0015 — the original is truncated (a 1,957-char run of
  `let tempN=mut.0;` with no body; E2004), rewritten as a 7-token isqrt loop; 0057 — a local
  `let chunk=` shadowed the enclosing function `chunk` (E4031), resolved by inlining into `main`.
- **Program-semantics repairs (April model output, migrate clean but wrong):**
  - exit-code returns instead of printing (`<val` from `main`): 0013, 0014, 0017, 0027, 0028, 0031, 0032 — now `j.print(...)`;
  - off-by-one / wrong loop bounds: 0010 (`i*!(i>n)` trial division), 0011 (n−2 iterations), 0012 (`i<n`);
  - C-style truncation where Python floor/mod semantics are expected: 0005 (mean), 0006 (mod), 0026 (floor div), 0033 (divisible), 0019/0048 (odd test `x-x/2*2==1` fails for negatives → `x%2!=0`);
  - bubble sort with a discarded `arr.set(...)` result (value semantics; lint `discarded-value-result`): 0042, 0043 → `arr=arr.set(...)`;
  - rotation direction and empty-list division by zero: 0054, 0055; empty/short input crashes: 0058, 0059;
  - lint `mut-flag-if` warnings cleared with expression-`if`: 0016, 0034, 0035, 0051.
- `tkc --lint` on the final 60: 0 errors, 0 warnings (hints only).

## Compiler faults worked around (need stories under Epic 127)

All three reproduce in `--legacy` mode on the untouched 851f6d8b originals with tkc 2.8.0,
and the April Gate-1 run (`benchmark/results/gate1_v5_1000.json`) had 0002/0007/0049/0056
at 120/120 — so they are regressions since the Gate-1 compiler, not program bugs.

1. **`j.print` of an i64 ≥ 2^32 prints garbage or segfaults**, even for a literal:
   `m=p;i=j:std.json;f=main():i64{j.print(4294967296);};` → exit 139. Affects 0002, 0007, 0012
   (expected values up to 7.3e13). Workaround: `i=o:std.io; … o.println("\(result)")`.
2. **`j.print` of an `@i64` that came back from a user function (or `.map`/`.filter`) prints it as
   a byte string** — `f=f2(a:@i64):@i64{<a};` then `j.print(f2(input))` on `[122,5]` prints `"z"`;
   the same array built by `r=r+@(...)` in `main`, or `f2(input)+@()`, prints `[122,5]`.
   Affected 0049, 0051, 0056, 0058 (and 0053, which passed only because its inputs never start with
   a printable byte). Workaround: inline the helper into `main`.
3. **`j.print` of a nested array (`@@i64`) prints element pointers** (`[4372358280,…]`), whether built
   in `main`, from a literal `@(@(1;2))`, or from json handles. Affects 0057 (chunk). Workaround:
   manual `"[\(s.join(",";parts))]"` + `o.println`. (Also noted: `arr.slice(i;k)` on an `@i64` compiles
   and returns zeros — probably UFCS resolving to `str.slice`.)

`--migrate` gap: `arr[j]=v` becomes a bare `arr.set(j;v)` (0042/0043), which is a no-op under value
semantics; the migrator should emit `arr=arr.set(j;v)`.
